# V2 使用说明

在项目目录运行 `node server-v2.js`，访问控制台原地址。V2 使用 `public/index-v2.html`；`server.js` 与 `public/index.html` 保持原样。运行配置仍使用原来的 `config.json`、`metadata.json`，也支持原有 `DATA_DIR`。更新后重启 V2 并刷新页面。

## 自定义上游与监查

测试台填写上游 slug 后，发送测试会严格指定该上游。留空则使用下拉选择。点击“加入监查列表”，或点击失败结果中高亮的上游名称，将该上游加入结果所对应模型的上游面板。收录会持久保存并在后续探测时保留；需要参与请求时，在面板中选择“优先”。

错误中的候选名称只从网关明确返回的上游清单字段提取；本次测试目标也提供快捷收录按钮。未经验证的名称不表示该渠道实际可用。

上游行内的“删除”会清理该模型的优先、排除和监查设置，并持久保存删除状态；重新探测不会自动加回。需要恢复时，在测试台手动加入即可。

## 指标排序

点击“探测”后，按实际管道读取其公开 endpoint 接口：Vercel 规划器使用 Vercel 数据，OpenRouter 直连使用 OpenRouter 数据。面板显示来源、采集时间和指标；切换排序会立即重排，缺失值置后；没有数据的指标和来源说明静默隐藏。

列表排名以 `#1`、`#2` 等编号显示；没有数据的上游也保留编号，仅隐藏数据。有数据的上游按当前指标排序，其他上游保持原顺序；全部无数据或选择网关智能选时保留发现顺序。订阅模型区域开头说明这一规则。列表排名与手动设置的尝试优先级分别显示。

- 最低成本：按输入 100 万 + 输出 100 万 token 的基础报价合计升序，同时显示输入、输出单价（美元/百万 token）。这是比较口径；阶梯、缓存、请求附加费用和峰时定价以网关为准。
- 最快首字：P50 首字延迟升序，统一显示毫秒。
- 最高吞吐：P50 吞吐降序，显示 token/秒。
- 多个 endpoint 归属于同一上游时，各指标取该上游最优 endpoint 值；成本的输入、输出价格来自同一个 endpoint。
- 网关智能选：网关没有公开可复现的完整排名和数值分数，面板保留发现顺序。

Vercel 性能指标窗口为近 1 小时；OpenRouter 为接口字段标注的近 30 分钟。数据是探测时快照，不会自动连续采集。列表的展示排序不改变手动保存的尝试顺序；“全选优先”会按当前展示顺序保存。

## 上游测速

选择订阅模型后默认勾选其全部上游，可逐项勾选或使用“全选上游”“清空选择”，然后点击“开始批量测速”。列表为空时可点击“探测供应商”，或在测试台手动收录。所选供应商逐个测速，每完成一项立即更新同一张表，失败项仅显示“失败”并继续下一项。每家供应商最多生成 1024 token，超时 120 秒，会消耗订阅额度。

完成后默认按生成速度降序排列；点击对应表头可按生成速度、体感均速、输入/输出/缓存读价格、5m/15m/1d 可用性降序排列，首包延迟升序排列。缺失值留空并置后，相同数值保留原顺序；整列没有数据时隐藏该列。

计时在本服务端执行，包含本服务到网关的网络时间，不包含浏览器到本服务的网络时间。页面开头说明以下口径：

- 生成速度：上游报告的 `usage.completion_tokens` 除以首个至最后生成片段的时间，单位 token/s。生成片段包含正文和已返回的推理片段；token 统计可能包含推理。该值是基于流片段的观测均速，受缓冲、分块影响。
- 体感均速：相同 token 数除以请求发起至流结束的总耗时，包含等待时间，单位 token/s。
- 首包延迟：发起上游请求至读取到首个非空响应数据块的时间，单位 ms；心跳或角色事件也可能是首包，因此不等同正文首字延迟。

缺少有效 token 数时隐藏两项速度，不以字符数估算；仅一个生成片段时隐藏生成速度。流提前断开、供应商未确认或与指定供应商不符时，报告测速失败。

测速完成后，按本次响应确认的网关及实际供应商获取公开数据；查询时间不计入测速。价格以美元/百万 token 显示输入、输出、缓存读的基础报价，并不代表本次账单。多 endpoint 分行展示，避免将不同端点的价格和可用性混为一个结果。缺失值静默隐藏，零价格与 0% 可用性保留。

可用性为接口报告的历史百分比：OpenRouter 读取 `uptime_last_5m` 和 `uptime_last_1d`，Vercel 读取 `uptime_last_15m` 和 `uptime_last_1d`。数值已为百分比，不再乘 100。它们与本次单次测速分别展示。

参考：[Vercel endpoint API](https://vercel.com/docs/ai-gateway/sdks-and-apis/rest-api)、[Vercel 可用性定义](https://vercel.com/docs/ai-gateway/models-and-providers/uptime)、[OpenRouter 流式响应](https://openrouter.ai/docs/api_reference/streaming)、[OpenRouter usage](https://openrouter.ai/docs/cookbook/administration/usage-accounting)。

## 测试

执行 `node --test tests/server-v2.test.cjs`。测试使用隔离内存配置和模拟响应，覆盖输入校验、鉴权、收录持久化、探测保留、来源与单位、排序、错误转义、空数据显示、流式测速及异常结束，不会发送真实推理请求。
